## 1. 能力概述

流程事件自动推送 **企业微信 / 钉钉** 工作通知（应用消息），覆盖三类事件：

| 事件 | 触发时机 | 通知对象 | 消息形态 |
|------|---------|---------|---------|
| 任务待办 | 任务创建 / 重新创建（create / recreate） | 任务办理人（候选人） | 企微 textcard / 钉钉 link，点击跳转待办页 |
| 任务超时 | 流程超时调度（timeout） | 任务办理人 | 同上 |
| 实例终态 | 实例结束（审批通过/终止/撤销等终态） | 流程发起人 | 结果通知，点击跳转实例详情 |

催办（urge）走**站内通知**（NotificationService），不推送 IM。

核心特性：

- **渠道凭据按租户独立配置**：每租户每渠道一行 `wf_im_channel_config`，secret 以 AES-256-GCM 加密入库，接口不回显，编辑留空 = 保留原值
- **fail-closed**：租户未配置/未启用渠道即不推送；多租户模式下事件缺少租户来源（快照与上下文均缺失）时放弃发送，绝不兜底猜租户
- **事务安全**：监听 `AFTER_COMMIT` 异步执行，事务回滚不产生幽灵推送；推送失败由 `ReliableEventConsumer` 按实例退避重试
- **零 DDL 用户映射**：复用 `sys_social_user` 社交绑定表，企微走个人中心扫码绑定，钉钉支持管理端手动录入企业 userid

## 2. 架构与事件流

```
FlowLong 引擎事件
  │ AFTER_COMMIT + @Async("workflowExecutor")
  ▼
ImNotifyEventHandler          # 事件过滤：create/recreate/timeout + 实例终态；租户来源解析（事件快照优先）
  │ ReliableEventConsumer.consume（失败退避重试）
  ▼
ImNotificationRouter          # 租户 → 过滤启用渠道 → 解析用户绑定 → 逐渠道扇出
  ├── ImUserBindingResolver   # 系统用户 → 企业 userid（sys_social_user）
  ├── WeComChannel            # 企微：token 缓存+失效强刷，textcard 消息
  └── DingTalkChannel         # 钉钉：token 缓存+失效强刷，link 消息，unionId→userid 转换
```

**失败语义**（与 `ReliableEventConsumer` 重试契约对齐）：

- 无启用渠道 / 无目标用户：no-op 直接返回（不抛异常，避免功能关闭时审计表噪音）
- 单渠道失败、其他渠道有成功：warn 日志，不抛（重试会给成功渠道重复推送）
- 全部启用渠道零成功：抛 `IllegalStateException`，交由消费模板退避重试

**多租户租户来源**：事件发布时刻的快照优先（异步消费线程上下文可能失真），缺失退回当前线程 `TenantContextHolder`；单租户模式（`tenant.enable=false`）保持历史行为按默认租户推送，开闸后 fail-closed。

## 3. 渠道配置

### 3.1 配置表 `wf_im_channel_config`

| 列 | 说明 |
|----|------|
| `tenant_id` | 租户 ID（非租户模式视作租户 1），与 `channel` 联合唯一 |
| `channel` | 渠道标识：`wework` / `dingtalk` |
| `enabled` | 是否启用（0/1） |
| `corp_id` | 企微 corpId（钉钉渠道为空） |
| `app_key` | 钉钉 appKey（企微渠道为空） |
| `agent_id` | 应用 agentId |
| `secret` | 应用 secret（AES-256-GCM 加密存储，接口不回显） |

### 3.2 管理页

管理端「**流程管理 → IM 通知配置**」（菜单 id=266，路由 `/workflow/im-config`）：租户下拉 + 双渠道行编辑，保存后即时生效（无缓存预热，按次读取）。

### 3.3 渠道侧准备

**企业微信**：在企业微信后台创建自建应用，获得 corpId / agentId / secret；应用需开启「工作通知」可见范围包含目标用户。

**钉钉**：在钉钉开放平台创建企业内部应用，获得 appKey（Client ID）/ appSecret / agentId；应用需申请「通讯录只读」权限用于 unionId→userid 转换与消息下发。

## 4. 账号绑定（系统用户 ↔ 企业 userid）

复用 `sys_social_user` 表，**零 DDL**：

| source | 绑定方式 | userid 来源 |
|--------|---------|------------|
| `wework` | 个人中心「社交绑定」企微卡片扫码绑定 | 行内 `open_id` 即企微 userid |
| `dingtalk_corp` | 管理端手动录入（用户管理 IM 绑定弹窗） | 行内 `open_id` 即钉钉 userid |
| `dingtalk` | 个人中心钉钉扫码绑定 | `union_id` 非空时经钉钉 API 转换（按租户凭据，转换结果缓存） |

未解析到绑定的用户在扇出时静默跳过（计数记日志），不影响其他用户推送。

## 5. API 端点与权限码

| 方法 | 路径 | 权限码 | 说明 |
|------|------|--------|------|
| GET | `/admin-api/workflow/im-config` | `workflow:im:config:list` | 按租户查询渠道配置（secret 不回显） |
| PUT | `/admin-api/workflow/im-config` | `workflow:im:config:edit` | 保存渠道配置（upsert，secret 留空 = 保留原值） |
| DELETE | `/admin-api/workflow/im-config` | `workflow:im:config:delete` | 删除渠道配置 |
| POST | `/admin-api/workflow/im/test` | `workflow:im:test` | 发送测试通知（校验凭据与绑定，指定用户实测链路） |

## 7. 常见问题（FAQ）

**Q1：配好了渠道但收不到推送？**
按顺序排查：① 渠道行 `enabled=1`；② 目标用户有对应 source 的绑定行且 `open_id` 非空；③ 应用侧可见范围/通讯录权限覆盖目标用户；④ 后端日志搜 `ImNotificationRouter` / `ImNotifyEventHandler`——「缺少租户来源」「所有启用渠道均未成功」均有明确 warn/error。

**Q2：企微绑定后 userid 对不上？**
`wework` 绑定采用「绑定 openId 即企微 userid」假设，要求绑定扫码所用企微应用与发消息应用**同属一个企业且 userid 口径一致**（企业微信自建应用内扫码满足）。跨应用场景请改用管理端手动录入。

**Q3：secret 改了要不要重启？**
不需要。配置按次读取，token 缓存按凭据分桶（tenantId 维度），凭据变化后 token 失效自动强刷。

**Q4：推送会重复吗？**
单渠道失败但其他渠道有成功时不重试（避免重复）；全部渠道零成功才退避重试，重试幂等键为实例 ID + 事件源。

**Q5：多租户下各租户凭据隔离吗？**
是。配置、token、unionId 转换缓存均按 tenantId 隔离；异步链路依赖事件发布时刻的租户快照，无快照且无上下文时放弃发送（fail-closed）。
