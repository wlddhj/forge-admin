# AI 智能审批与 AI 智能路由指南

> 适用模块: `forge-module-workflow`
> 适用人员: 流程设计者 / 流程管理员 / 后端开发
> 关联文档: [工作流使用说明](01.workflow-usage.md) §8 / [条件节点指南](02.condition-node-guide.md) §3.1
> 交付版本: AI 审批(迭代一+异步化) / AI 智能路由(2026-10-26, commit 7d476e9)

---

## 1. 两个能力一句话区分

| | AI 智能审批 | AI 智能路由 |
|---|---|---|
| 作用位置 | **审批节点**(type=1/3) | **分支网关**(条件 4 / 包容 9 / 路由 23) |
| AI 决定什么 | 这条任务**通过 / 驳回 / 转人工** | 流程**走哪条分支 / 跳哪个节点** |
| 执行时机 | 任务创建后**异步**(事务提交后 workflowExecutor 线程) | 流程到达网关时**同步**(默认限时 15s) |
| AI 失败降级 | 按 fallbackStrategy:转人工 / 默认通过 / 默认驳回 | 落回分支条件判断(SpEL)→ 默认分支 |
| 审计表 | `wf_ai_approval_record` | `wf_ai_route_record` |
| 模型变量输入 | 流程变量 + 节点名 | 流程变量 + **候选分支清单**(nodeKey+分支名) |

二者**互补且可组合**:同一流程里"AI 路由决定走哪条线、AI 审批决定线上节点过不过"。

## 2. AI 智能审批

### 2.1 机制

1. 任务创建时 `CompositeTaskListener` 解析节点 `extendConfig.aiApproval`,启用则发布 `WorkflowAiApprovalEvent`(同步段只解析配置,不调 LLM,不阻塞引擎事务)
2. 事务提交后由 `AiApprovalEventConsumer` 在 `workflowExecutor` 线程池执行;幂等守卫:任务已被人工办理则放弃
3. 按节点 `timeoutSeconds`(默认 30s)限时调用 LLM,输出契约 `{"decision":"APPROVE|REJECT","confidence":0-100,"reasoning":"..."}`
4. 置信度 ≥ 阈值才执行;否则转人工。超时/异常按 `fallbackStrategy` 降级
5. 结果落 `wf_ai_approval_record`,自动通过/驳回同时写 `wf_approval_comment`(操作人"AI系统")

### 2.2 设计器配置

审批节点抽屉打开「AI 审批」开关:

| 配置 | 说明 | 默认 |
|---|---|---|
| provider / modelName | 模型提供商与名称(走 `ai_model_config` 已配置模型) | 系统默认模型 |
| confidenceThreshold | 置信度阈值(0-100),低于转人工 | 80 |
| fallbackStrategy | 失败回退:MANUAL / DEFAULT_PASS / DEFAULT_REJECT | MANUAL |
| customPrompt | 审批要点提示词 | 空(用内置审批提示词) |
| timeoutSeconds | 决策限时(秒) | 30 |

### 2.3 排查

- 记录表:`SELECT * FROM wf_ai_approval_record ORDER BY id DESC LIMIT 20;`
- 后端日志关键字:`开始执行AI审批` / `AI审批自动通过` / `AI审批放弃执行`

## 3. AI 智能路由

### 3.1 机制与降级链

流程到达网关时,引擎按以下顺序决定分支(前一步失败自动落下一步,**全程不抛异常**):

```
① 审批人显式指定分支(FlowDataTransfer 指定 key,跳过一切)
② AI 决策(节点 callAi 非空时):LLM 从候选分支清单中选择
③ SpEL 条件求值(按 priorityLevel 升序,组内 AND / 组间 OR)
④ 默认分支(conditionList 为空的那条)
都没有 → 引擎抛 "Not found executable ConditionNode"(发起校验会提前拦截)
```

AI 决策内部:构建提示词(自定义规则 + 候选分支清单 + 流程变量摘要,敏感键脱敏)→ 限时调 LLM(`LlmClient.chat`,模型经 `AiModelResolver` 解析)→ 解析 `{"nodeKeys":[...],"confidence":0-100,"reasoning":"..."}` → nodeKey 精确匹配、分支名兜底 → 置信度阈值校验。

- **条件/路由网关**(单选):取第一个命中分支;路由网关命中即跳转 `route:目标节点`
- **包容网关**(多选):AI 可同时激活多条分支,任务并起

### 3.2 设计器配置

条件/包容/路由三类网关顶部有「**AI 路由**」按钮(启用后变黄色「AI 路由·已启用」):

| 配置 | 说明 | 默认 |
|---|---|---|
| 路由提示词 | 描述路由规则,如"金额大于 1 万且 VIP 走高额审批" | 内置通用文案 |
| 模型名称 | 留空走系统默认模型 | 空 |
| 决策超时(秒) | 5-60 | 15 |
| 置信度阈值 | 0-100,低于不采纳 AI 选择 | 80 |

> **强制规则**:启用 AI 路由的网关**必须保留一个无条件默认分支**,否则发起流程时被 400 拦截(防 AI 与条件双失败导致引擎卡死)。

### 3.3 决策状态与审计

每次决策(含降级)落一条 `wf_ai_route_record`:

| 字段 | 说明 |
|---|---|
| gateway_node_key / gateway_type | 网关节点与类型(4/9/23) |
| candidate_branches | 候选分支 JSON |
| selected_branches | 命中并实际生效的分支 nodeKey(逗号分隔;降级时为空) |
| confidence / reasoning / raw_response | 置信度 / AI 理由 / 原始响应 |
| status | `SUCCESS` / `FALLBACK`(未匹配或不可解析) / `LOW_CONFIDENCE` / `TIMEOUT` / `ERROR` |

```sql
-- 最近决策与生效分支
SELECT id, gateway_node_name, selected_branches, status, confidence, reasoning, create_time
FROM wf_ai_route_record ORDER BY id DESC LIMIT 20;
```

> 建表 SQL:`sql/upgrade-20261026-ai-route-record.sql`(dev 库无 Flyway,新环境须手工执行;`init-workflow.sql` 已同步)。

### 3.4 注意事项

1. **同步决策**:AI 路由在流程流转事务内同步执行(默认 15s 上限)。发起/审批接口的耗时会包含这次 LLM 调用,高并发流程慎用或调小超时;变量尽量在发起时或前置触发器写好。
2. **空配置陷阱**:引擎部署时以 `NON_EMPTY` 序列化重写模型 JSON,`extendConfig.aiRouting` 若为空对象会被整键剔除。设计器已自动注入默认值防御;**手写/外部导入模型 JSON 时**,aiRouting 至少要含一个非空字段(如 confidenceThreshold)。
3. 并行分支(8)没有路由语义,不提供 AI 路由入口。
4. LLM 返回的分支标识必须能对上候选(nodeKey 精确或分支名 trim 相等),幻觉分支按 FALLBACK 降级,不会走错。
5. 后端日志关键字:`AI路由决策`(命中) / `AI路由未命中`(降级,含状态) / `AI路由已标记(callAi)但 extendConfig.aiRouting 缺失`(配置丢失)。

## 4. 组合示例

```
[发起人] → [触发器:计算风险等级] → [AI 路由条件网关]
                                        ├─ AI 选"高风险" → [AI 审批节点(AI初筛)] → [总监人工复核]
                                        ├─ 条件命中"低风险" → [主管审批]
                                        └─ 默认分支 → [主管审批]
```

- 触发器写 `riskLevel` 变量 → AI 路由读变量+规则选分支 → 高风险线上的 AI 审批节点自动初筛,低置信度自动转人工复核
- 任一 AI 环节失败都有确定性降级路径,流程不会卡死

## 5. 常见问题

### Q1: AI 路由启用了但流程走的还是条件分支?

A: 查 `wf_ai_route_record.status`——大概率是 `FALLBACK/LOW_CONFIDENCE/TIMEOUT/ERROR`(AI 未被采纳),看 reasoning/raw_response 定位;`SUCCESS` 却走错才是 bug。

### Q2: AI 审批一直不执行?

A: AI 审批是异步的,事务提交后才跑;确认任务仍在活动表(幂等守卫)、`ai_model_config` 有启用模型。日志搜 `AI审批放弃执行`。

### Q3: 手写模型 JSON 配了 callAi 和空 aiRouting,不生效?

A: 引擎 NON_EMPTY 序列化把空对象剔除了(见 §3.4-2)。给 aiRouting 至少一个非空字段,或用设计器重新保存。

### Q4: 包容网关 AI 能同时走几条?

A: 能,返回的 nodeKeys 列表里命中的所有分支都会激活;全不命中降级走 SpEL/默认分支。
